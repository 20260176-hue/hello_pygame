1. 주요 실습 내용1.1 PyInstaller 환경 구축 및 설치Python 스크립트를 독립된 실행 파일로 빌드하기 위해 가장 먼저 pyinstaller 라이브러리를 설치하였습니다. 터미널에서 pip install pyinstaller 명령어를 사용하였으며, 설치 완료 후 pyinstaller --version을 입력하여 정상적으로 설치되었는지 확인하는 과정을 거쳤습니다.  
1.2 실행 파일 경로 최적화 (resource_path)PyInstaller의 --onefile 옵션을 사용하여 빌드하면 실행 시 파일들이 임시 폴더인 sys._MEIPASS에 압축 해제됩니다. 이 때문에 코드에 작성된 일반적인 상대 경로로는 파일을 찾지 못하는 문제가 발생합니다. 이를 해결하기 위해 빌드 환경에서는 임시 폴더 경로를, 개발 환경에서는 현재 폴더 경로를 반환하는 resource_path 함수를 도입하였습니다.  
1.3 리소스 로드 방식 및 빌드 옵션 적용게임 내 배경음악 등 외부 자산을 불러오는 모든 코드를 resource_path() 함수로 감싸 환경에 관계없이 파일을 정상적으로 참조하도록 수정하였습니다. 최종 빌드 시에는 파일 하나로 통합하는 --onefile, 실행 시 터미널 창을 숨기는 --windowed, 그리고 사운드 파일을 실행 파일 내부에 포함하는 --add-data 옵션을 조합하여 명령어를 구성하였습니다.  
2. 오류 해결 사례 (Troubleshooting)
첫째, Script file does not exist 오류가 발생하였습니다.
이는 터미널의 현재 작업 위치가 game.py 파일이 있는 폴더와 달랐기 때문에 발생한 문제입니다. 이를 해결하기 위해 cd 명령어를 사용하여 프로젝트가 저장된 정확한 디렉터리로 이동한 후 빌드를 재시도하였습니다.  
둘째, resource_path 함수 관련 TypeError가 발생하였습니다.
함수 호출 시 정의된 것보다 많은 인자를 전달하여 발생한 오류였습니다. 함수가 단일 인자(상대 경로)만 받도록 설계되었음을 확인하고, 코드 내 호출 부분을 수정하여 인자 개수를 맞춤으로써 문제를 해결하였습니다.  
셋째, 에셋 파일을 찾을 수 없다는 Unable to find WAV 오류가 발생하였습니다.
빌드 시 포함할 배경음악 파일명이 실제 폴더 내 파일명과 다르거나 공백이 포함되어 생기는 문제였습니다. 파일 이름을 정확히 대조하고, 공백이 있는 파일명은 큰따옴표("")로 감싸 명령어를 작성하여 해결하였습니다.  넷째, Thonny 편집기에서 BrokenPipeError가 발생하였습니다.Thonny의 내부 실행 프로세스와 터미널 간의 연결 충돌로 인해 나타나는 증상이었습니다. Thonny 메뉴의 'Stop/Reset backend' 기능을 실행하여 프로세스를 초기화함으로써 정상적인 실행 환경을 복구하였습니다.3. 최종 결과 및 마무리모든 오류를 수정한 후 pyinstaller --onefile --windowed --add-data "653804__...wav;." --name=QuantumSlither game.py 명령어를 통해 최종 빌드를 완료하였습니다. dist/ 폴더 내에 생성된 QuantumSlither.exe 파일은 배경음악을 포함한 상태로 단독 실행이 가능함을 확인하였습니다. 본 실습 과정은 practice/week11.md에 기록하였으며, GitHub에 최종 커밋하여 실습을 종료하였습니다.
